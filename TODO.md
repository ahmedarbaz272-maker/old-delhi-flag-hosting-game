# Delivery Checklist

## 1. City, player, movement, camera, and collision
- [ ] Build a connected, explorable fictional Indian-city environment inspired by the supplied map and city references, not a collection of disconnected rooms. Include narrow streets, wider roads, historic-style buildings, shops/markets, alleys, courtyards, rooftops/terraces/passages where appropriate, industrial areas/warehouses, streetlights, signs, walls, barricades, NPCs, landmarks, patrol routes, alternative routes, skyline, and a distinct final secured zone. Use procedural geometry and documented placeholders only where supplied/approved assets do not cover the role; keep performance appropriate for desktop and mobile.
- [ ] Implement walk/run/sprint/crouch/jump/turn/interact, stop/resume, stair climbing, collision against buildings, walls, gates, and barricades, floor/edge handling, and valid checkpoint/restart behavior. Do not allow interaction outside its radius, walking through collision, falling through floors, or bypassing the tower staircase.
- [ ] Support first-person and third-person cameras; use mouse look and smooth, collision-aware camera movement; camera switching does not reset mission progress.
- [ ] Desktop defaults: WASD move; mouse look; Shift sprint; Ctrl crouch; Space jump; E interact/recruit; M map; C camera; Esc pause. Keep keyboard bindings configurable. On mobile provide safe-area-aware responsive/landscape UI, on-screen joystick, touch-look, sprint/crouch/jump/interact/camera/map/pause buttons, large touch targets, portrait-mode guidance as needed, optional fullscreen, and prevent page scrolling during play; do not require pointer lock on mobile.

## 2. Sixteen gathering sites, crowd, and progress
- [ ] Define exactly these 16 unique, editable locations in centralized data: Old Quarter Square; Lantern Market; Bricklane Junction; Railway Yard; Riverside Blocks; Clocktower Ward; Foundry Street; East Bazaar; Abandoned Depot; Narrow Alley Quarter; Warehouse Row; South Courtyard; Stonebridge; Industrial Edge; Outer Assembly Road; Central Gathering District.
- [ ] Every site has a unique ID/name, visible landmark, discoverable marker, configurable position/radius/crowd target/capacity/difficulty/security/audio profile, objective description, recruit interaction, completion state, and progression contribution. Entering a site reveals it and updates the local objective/map; crowd progress is calculated from configured requirements, never double-counted.
- [ ] Implement friendly, fictional, non-graphic crowd gathering with idle/walk/talk/join/follow/regroup/wait states, visible dialogue/feedback, bounded reusable NPCs, formation slots and spacing, simple obstacle avoidance/recovery, and crowd limits. Followers/background actors must not stack, spawn inside walls, block controls/stairs/tower, or accumulate after restart.
- [ ] Display and persist correct counts (e.g. `Gathering Locations: 5 / 16`) and keep the final zone locked until all required locations are complete.

## 3. Security, detention, and restart
- [ ] Implement configurable AI security profiles and patrol routes with a modular state machine covering Idle, Patrol, Observe, Suspicious, Investigate, Alert, Pursue, Search, Detain, and Return to Patrol.
- [ ] Detection uses distance, field of view and line-of-sight checks/raycasting, movement/visibility, restricted boundaries, alert level and time in view; security must not detect through solid walls or arbitrary distances. Use browser-suitable waypoints/pathfinding, staggered perception updates, and distance-based simulation.
- [ ] On catch, stop movement, cancel any flag hosting, show a short non-graphic detention/failure sequence, explain detection, and display reason plus crowd progress and locations complete out of 16. Provide Restart Mission and Return to Main Menu.
- [ ] Restart resets player position/motion, NPC/security alert states, followers, progression according to restart scope, current objective, hosting state/progress, audio/UI overlays, and temporary objects. No stale AI, duplicate NPCs, softlocks, or phantom completion. Provide current-mission/full-game restart where practical.

## 4. Secured final zone and exact flag hosting
- [ ] Build a visually distinct mostly-open assembly ground with multiple barricades, fences/gates, checkpoints, guard posts, patrols, observation positions, floodlights, warning signs, distant skyline, central tall watchtower, visible staircase, top platform, and flagpole. Tower/stairs/collision are real 3D geometry; final-zone access is gated until all 16 locations are completed.
- [ ] Implement the hosting state flow `LOCKED → AVAILABLE → APPROACHING → READY_TO_HOST → HOSTING_IN_PROGRESS → HOSTING_INTERRUPTED / HOSTED → MISSION_COMPLETE`. Hosting is impossible remotely: validate that the player is on the actual tower platform and near the flagpole; only valid interaction starts it; accurately show progress; interruption follows configured rules; detention cancels hosting; success/state transition/victory sequence occurs exactly once; restart restores the initial flag state.
- [ ] Use the exact supplied `gyanu` image at `public/assets/flags/gyanu.png` (or documented actual path): preserve original pixels/content/aspect/transparency; do not redraw, recolor, crop, distort, replace, or invent a flag. Attach it as a texture to a suitable pole/flag mesh with recognizable subtle cloth motion; provide loading failure message and retry.
- [ ] Animate the flag rising into hosted position and begin cloth motion; show mission-completed victory with 16/16 and elapsed time/mission statistics, plus Play Again and Main Menu. `HOSTED` is the sole final success—never flag capture/theft/retrieval/collection.

## 5. Interface, navigation, accessibility, local saves, and audio
- [ ] Provide loading/progress/status/retry; main menu with game title, Start/Play, Continue when saved progress exists, Mission Progress, Controls, Settings, Credits, About, Privacy, Accessibility; mission briefing; HUD with gathering count, objective, player status, interaction prompt, detection indicator, pause, and map/minimap; pause with Resume/Restart/Settings/Main Menu; settings and controls; functional map; failure and victory screens.
- [ ] Map/compass shows the player, 16 objective markers, current objective/route, district legend, FLAG HOSTING ZONE, zoom/pan and marker states that reflect actual discovery/progression. The map is functional, not decorative.
- [ ] Keep text readable and high-contrast; menu keyboard navigation/focus indicators and descriptive labels; color-blind-safe states; reduced motion; adjustable sensitivity/audio; optional subtitles; large touch targets and responsive layout. Do not make gameplay depend solely on color, audio, or tiny indicators.
- [ ] Use one authoritative game/mission state and robust local saves for discovered/completed location IDs, crowd/progress/current mission, settings/camera preference and save version. Validate loaded saves, handle missing/corrupt data safely, and reset New Game correctly (with confirmation where appropriate). No passwords, payment, identity data, or unnecessary personal data. Optional PWA/offline caching must stay bounded and must not claim offline play beyond verified behavior.
- [ ] Provide suitable optional/procedural city ambience, footsteps, interaction, detection and completion feedback where included; audio absence must not prevent the game from running. No generated audio without separate approval.

## 6. Visual assets, performance, and maintainability
- [ ] Deliver the user-requested colorful, polished, stylized runner-game 3D visual quality (“Subway Surfers type graphics”) with detailed original buildings, landmarks, crowds, and security characters; do not copy Subway Surfers characters, logo, or art assets. Use the four already approved/generated GLBs (runner, gatherer, guard, bazaar) with the original procedural city kit; catalog access was unavailable for this project, and no additional credit spend is authorized by this plan. Generated audio remains out of scope.
- [ ] Use Three.js, TypeScript, Vite, HTML/CSS and WebGL2; pin minimal compatible dependencies; no paid API/backend/account/multiplayer. Maintain modular code/configuration for location data, world geometry, player/camera/collision, crowd/security AI, mission objectives, UI/mobile controls, map, audio, and saves.
- [ ] Optimize using delta time/fixed-step starter engine, reusable geometries/materials/objects, instancing/LOD/frustum culling, efficient collision, pooled transient effects, staggered AI, distance-based NPC simulation, lazy asset loading, configurable crowd/shadows/quality/render scaling. 60 FPS is a target only; report actual measured figures only.
- [ ] Show helpful WebGL2-unavailable and asset errors; clean up listeners and temporary resources; prevent duplicate loops, unhandled promise rejections, unsafe HTML injection, downloaded-script execution, and frontend secrets. Keep generated/imported assets licensed/provenanced and maintain an asset-license inventory.

## 7. Production build, GitHub Pages, and documentation
- [ ] Production Vite build succeeds and all required local assets load; configure correct subdirectory base path for the GitHub Pages repository; add GitHub Actions Pages deployment without modifying the unrelated company website/repository.
- [ ] Provide and execute checks for startup/rendering, movement/camera/collision, 16 objective states/progress, crowd behavior, security patrol/LOS/failure/restart, locked final state, physical stairs, correct exact flag texture, HOSTED exactly once, menus/mobile controls, production build and deployment paths. Fix critical errors/softlocks; include pass/fail, known issues and reproduction steps rather than claiming untested results.
- [ ] Document install/dev server/build/preview, GitHub Pages deployment and base path, MIME types for any GLB/glTF/textures/audio, HTTPS, desktop/mobile testing, assets/licenses, and free-hosting limits. Clearly state remaining limitations and how to test the live game.
